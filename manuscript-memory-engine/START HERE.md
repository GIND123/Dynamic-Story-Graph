# START HERE: Manuscript Memory Engine

This folder is a ready-to-build project. Claude Code builds the whole thing from `CLAUDE.md`. You drive it with the prompts below.

## What is in this folder

- `CLAUDE.md` the complete, binding build specification. This is what Claude Code reads.
- `.env.example` environment template (copy to `.env`, add your key for the live demo).
- `.gitignore`
- `START_HERE.md` this file.

Everything else (all application code, Docker files, tests, README) is generated by Claude Code under the spec.

## Prerequisites

1. Docker Desktop installed and RUNNING. The project runs entirely in containers.
1. Node.js 18+ and Claude Code installed: `npm install -g @anthropic-ai/claude-code`, then run `claude` inside this folder.
1. Optional, only for the live demo: an Anthropic API key. The full build and all tests run WITHOUT one, in FAKE mode.

## Two different “Claude” keys (do not confuse them)

- Claude Code, the tool building the project, uses your normal Claude login. That is what runs when you type `claude`.
- The app’s runtime key is `ANTHROPIC_API_KEY` in `.env`. It is used only when you run the finished app in real mode to actually generate chapters. Leave `LLM_MODE=fake` until you want the live demo.

## How to start (4 steps)

1. Open a terminal in this folder.
1. `cp .env.example .env`  (for the live demo later, paste your key into `.env`).
1. Run `claude` to open Claude Code here.
1. Paste PROMPT 1 below.

## PROMPT 1: kick off the build

```
This folder contains CLAUDE.md (the full build spec), plus .gitignore and
.env.example, already created. Use them; do not recreate those three.

Read CLAUDE.md in full before writing any code. Section 0 (operating
instructions), Section 3 (verified API contracts), and Section 13 (pitfalls)
are binding. Do not use older API patterns from your training data; where this
file specifies an API shape, use it. Re-fetch the structured outputs doc before
Phase 2 as the file instructs.

Then build the project in strict phase order (Phases 1 to 5, Section 10). For
each phase: implement it, write and run its tests, run ruff, confirm the
acceptance criteria pass, commit with a clear message, update DECISIONS.md, then
print a short PHASE COMPLETE report listing each acceptance criterion and its
pass/fail. Pause after a gate only if a criterion fails; otherwise continue.

Use FAKE LLM mode for all tests (no API key needed). Do not add anything from the
out-of-scope list in Section 15.

Start with Phase 1. First give me a one-paragraph plan and the file list you will
create in Phase 1, then proceed.
```

## Tighter control (phase by phase)

If you would rather inspect after each phase instead of letting it run, end PROMPT 1 with “Build only Phase 1 and stop.” Then advance with:

- `Proceed to Phase 2.`
- `Proceed to Phase 3.`
- … through Phase 5.
  After each phase it commits and prints a PHASE COMPLETE report.

## If something breaks

- A container is unhealthy or `make up` fails:
  
  ```
  A container is failing. Run `make logs`, find the root cause, fix it, and
  re-verify the current phase's acceptance criteria. Tell me what was wrong.
  ```
- You suspect an API changed since the spec was written:
  
  ```
  Re-fetch the latest Anthropic structured outputs documentation and the
  getzep/graphiti README. Reconcile any differences with CLAUDE.md Section 3,
  update the code, and log the changes in DECISIONS.md.
  ```
- A phase gate keeps failing:
  
  ```
  Do not proceed. Show me the failing test output, your diagnosis, and two
  options to fix it before changing anything.
  ```

## Run the live demo (after the build, optional)

1. In `.env`: set `LLM_MODE=anthropic` and paste your `ANTHROPIC_API_KEY`.
1. `make up && make seed`
1. Follow the demo block in the generated `README.md` (Section 12 of CLAUDE.md). The seed kills a character in chapter 2; you request chapter 3 and watch the system keep them dead, or catch the attempt, then open Neo4j Browser at <http://localhost:7474> to see the graph.
1. To prove the gate for free (no key): set `LLM_MODE=fake` and `FAKE_VIOLATION=1`, restart the worker, request a chapter, and watch it land NEEDS_REVIEW.
